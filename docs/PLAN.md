# Agent Receipt — 2주 검증 실행 계획 (v1, 2026-09-17)

**검증할 가설:** 코딩 에이전트를 쓰는 개발자에게 "에이전트가 Bash로 뭘 지우고 바꿨는지 보고 되돌리는 것"은 **낯선 사람의 CLI를 설치하게 만들 만큼** 큰 고통이다.
**이 테스트가 판정하지 않는 것:** 수익화 가능성, 장기 리텐션. 오직 "행동을 끌어내는가".
**병행 원칙:** ClearSpace·Fileio·Privune·Serenity·Doran·FixShot 등 기존 라인업은 유지. Agent Receipt는 병행 검증 트랙이며 기존 제품 유지보수 시간을 가져오지 않는다.

## 1. 사전 결정 규칙 (나중에 느슨하게 풀지 않음)

1. 타임박스: **09-17(목) ~ 09-30(수)**, 판정 **10-01(목)**. 빌드 기간 포함. 출시가 늦어지면 **측정 기간이 줄어들 뿐 마감은 안 늘어난다.**
2. 확인된 설치자가 **한 자리 수(≤9)면 KILL.** "더 열심히"가 아니라 "이 고통이 행동을 끌어낼 만큼 크지 않다"로 해석.
3. 애매한 구간은 기본값 PIVOT. 연장 없음.
4. 모든 기능·콘텐츠 1차 필터: **"이 결과물이 설명 없이 공유될 수 있는가?"** 통과 못 하면 v0에서 뺀다.
5. 인터뷰는 설치자 중 원하는 사람에게만(도구 안 opt-in 링크). 콜드 인터뷰 요청 안 함.

## 3. 모집·유통 (설치 요청 중심)

- **1차 콘텐츠 단위 = 도구가 직접 만드는 영수증 카드.** 예: "Claude가 `rm -rf build/` 실행 → 추적 안 되던 파일 3개도 삭제됨 → 한 줄로 복구". 경로·비밀은 `--share`에서 자동 마스킹.
- **Hermes 실시간 감지** (`hermes cron create`로 생성, 수동 편집 금지):
  - HN Algolia `search_by_date` — 09-17 실측: `"claude code"` 단독은 **주 631건**, `"rewind"` 단독은 무관한 글 위주 → 단일 키워드는 쓸 수 없음. **에이전트 단어 AND 손실 단어**(deleted / rm -rf / wiped / lost / undo / rewind) 조합 + OpenRouter 소형 모델로 "실제 파일 손실·복구 고민인가" 분류 → 통과한 것만 Telegram 알림(링크 + 답글 초안).
  - GitHub 이슈: `anthropics/claude-code`(rewind/checkpoint × bash/deleted), `openai/codex`(undo 제거 후 복원 요청 #44852 계열) — 고통이 가장 구체적인 채널. 우선순위 1.
  - Reddit(r/ClaudeAI, r/ChatGPTCoding, r/cursor): 이 환경에선 `.json` 403으로 확인 불가 → Hermes 서버에서 접근 확인, 막히면 OAuth 앱 등록 또는 제외.
  - **답글은 사람이 직접**, 문제를 실제로 해결할 때만, 제작자임을 밝힘. 자동 게시 없음.
- **최소 노출 약속(입력 지표):** Show HN 1회, 실시간 감지 스레드 답글 ≥15, 커뮤니티 글 ≥3. 이걸 채워야 "한 자리 수 = 고통 부족" 해석이 성립한다(아래 §5 참고).
- SafeUnfollow SEO 블로그 파이프라인: 독자층(인스타그램 사용자) 불일치 + SEO는 2주 안에 효과 없음 → **이번 검증에서는 제외**, 파이프라인 코드는 GO 이후 개발자 블로그용으로 재사용 검토.
- jonnylab.app 팝업 없음. 필요 시 닫을 수 있는 배너(새 탭 링크), 최저 우선순위.

## 4. 측정 정의 (Private 원칙 유지)

기본 텔레메트리 없음. `init` 때 **opt-in 익명 ping** 1회 질문(기본 N): `installed`, `3번째 세션 영수증 생성` 두 이벤트만, 경로·내용·명령 없음.

| 지표 | 정의 | 비고 |
|---|---|---|
| 확인된 설치자 | opt-in `installed` ping + 설치를 직접 알려준 사람(이슈·DM·답글) 중복 제거 | **판정 기준.** opt-in이라 실제보다 적게 잡힘을 감안해 기준을 정함 |
| 활성 사용자 | 실제 세션에서 영수증 ≥3개, 서로 다른 날 ≥2일 (ping 또는 스크린샷 동반 자기 보고) | |
| 강한 신호 | 실제 사고에서 restore 사용, 자발적 공개 공유, 미요청 기능 요청, 지불 의사 표명 | 건별 링크로 기록 |
| 참고용 | npm 다운로드, GitHub 스타·방문 | 봇·미러 잡음 때문에 판정에 안 씀 |

## 5. GO / PIVOT / KILL (10-01 판정)

| 판정 | 조건 | 다음 행동 |
|---|---|---|
| **GO** | 확인된 설치자 **≥25** AND 활성 **≥5** AND 강한 신호 **≥1** | Codex 어댑터, 설치자 인터뷰 5명, 유료화 가설 설계 |
| **PIVOT** | 설치자 10–24, 또는 설치 ≥25인데 활성 <5, 또는 강한 신호 0 | 신호가 몰린 쪽으로 한 번만 좁힘: ①훅 없이 "지난 세션 감사"(transcript만) ②Codex 전용(undo 공백) ③공유 카드/비용. 새 2주, 같은 규칙 |
| **KILL** | 설치자 **≤9** | 코드·학습 기록 후 종료. 재시작은 새로운 외부 증거(내 해석 아님)가 있을 때만 |
| **KILL (조기)** | D0에서 Entire 등이 같은 시나리오를 동등 이상으로 해결하고 차별점이 "더 예쁜 UI"뿐 | 빌드 전에 멈춤 → 2주를 기존 라인업에 반환 |

**짚어둘 가정:** "한 자리 수 = 고통 부족"은 노출이 충분했을 때만 참이다. 노출 약속(§3)을 못 채운 채 한 자리 수가 나오면 결과 해석은 달라지지만, **규칙 2에 따라 판정은 여전히 KILL**이다. 이 긴장을 미리 받아들이는 게 사후 합리화를 막는 비용이다 — 그러니 노출 약속을 먼저 지키는 게 실질적 방어선.

## 6. D0 결과 (09-17, 소스 코드 수준 확인) — 조기 KILL 게이트 **통과**

| 확인 대상 | 사실 (근거) | 우리 시나리오(Bash로 미추적 파일 + `.env` 삭제 후 파일 단위 복구) |
|---|---|---|
| Entire CLI `f143dc9` (09-16) | 스냅샷은 Stop(턴 종료) 시점에만 생성, Bash 훅 matcher 없음 · `filterGitIgnoredFiles`로 gitignored 파일 **명시적 제외** · rewind/restore 코드 **삭제됨**(CHANGELOG #1747, #2178) · 스냅샷은 리댁션 없는 raw blob | **해결 못 함.** 턴 안에서 생성→삭제된 파일, `.env`, 파일 단위 복구 모두 불가 |
| npm `agent-receipt` 0.2.0 | 훅(PostToolUse)으로 툴 호출 로그 → 세션 영수증(의도·비용·side effects·intent score), SQLite, PR용 Markdown | **해결 못 함.** Bash는 명령 텍스트만 기록, 실제 파일 변화 관찰·복구 없음. 단 **"영수증" 컨셉과 이름은 선점됨** |

**여기서 나온 반례 — 무시하지 말 것:** ★4.9k 도구(Entire)가 restore 코드 1,800줄 이상을 **스스로 지웠다.** 이유는 모르지만(복잡도? 사용량 부족?) "복구 수요는 가시성 수요보다 약할 수 있다"는 가설이 생긴다. 그래서 §4의 강한 신호에 "실제 사고에서 restore 사용"을 둔 게 핵심 판별 지표이고, 10-01 판정 때 restore 사용 0이면 PIVOT ③(공유 카드/가시성) 쪽 증거로 읽는다.

**포지셔닝 조정:** "영수증"은 이미 있는 말이다. 차별점은 **"Bash가 한 일까지 보고, 파일 하나만 되돌린다"** — 랜딩·Show HN 제목은 이 문장을 앞에 둔다.
